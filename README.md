## Структура проекта

```
Practise1/
├── Program.cs              // только Main и вызовы
└── Tasks/
    ├── Loops.cs            // циклы for
    ├── Conditions.cs       // if / else if / else + циклы
    ├── Arrays.cs           // массивы
    └── ArraysMethods.cs    // методы с параметрами, методы над массивами
```

Каждая задача это отдельный `public static` метод. В `Main` вызывается только нужный:

```csharp
using Practise1.Tasks;

static void Main(string[] args)
{
    Arrays.Task11();
}
```

**Сложности:**

Проверку границы ставим после действия, которое может её нарушить. Тесты подбираем так, чтобы они ломали код. Код надо сверять с собственным планом. ## Разобранные ошибки

Ошибки полезнее всего записывать: так они перестают повторяться.

| Ошибка | Причина | Как исправить |
| --- | --- | --- |
| `IndexOutOfRangeException` | индекс вышел за границы массива | цикл `i < arr.Length`, старт с `i = 0` |
| `OverflowException` при `new int[n]` | отрицательный размер массива | проверка `if (n <= 0)` до создания |
| «does not exist in the current context» | компилятор не нашёл имя: опечатка или нет `using` | проверить имя и `using` |
| «inaccessible due to its protection level» | метод найден, но закрыт | добавить `public` |
| Метод возвращает результат после первого элемента | `return sum;` стоит внутри цикла | вынести `return` на уровень после `for` |
| Проверка аргументов не работает на пустом массиве | проверка стоит внутри цикла, а он не выполняется | проверять аргументы до цикла, в начале метода |
| Диапазон из одного числа (`from == to`) даёт 0 | строгое `<` вместо `<=`, лишнее условие отрезает работу | убрать лишнюю проверку, тестировать граничные значения |
| Из метода с типом `int` нельзя вернуть текст | тип возврата задаётся один раз в сигнатуре | пока -1 как признак ошибки; позже исключения (`throw`) |
| Вместо значений выводится `System.Int32[]` | `Console.WriteLine(array)` вызывает `ToString()` у ссылочного типа и выводит имя типа | выводить элементы циклом (метод `PrintArray`) или `string.Join(", ", array)` |
| Программа зависла, ничего не выводит | условие цикла зависит от одной переменной, а внутри цикла меняется другая | переменная из условия должна меняться внутри цикла; спросить, нужен ли цикл вообще |
| Счётчик в цикле всегда равен 1 | `int i = 1;` объявлен внутри цикла и создаётся заново на каждом повторе | объявлять счётчик до цикла |
| Здоровье уходит в минус | проверка «не ниже 0» стоит не после вычитания (например, в `else if`) | проверять границу после действия, которое может её нарушить |
| Оружие «не ломается» | результат `UseWeapon()` получен один раз и повторно используется | вызывать метод заново для каждого удара |
| Код не делает то, что написано в плане | план и код разошлись (отнимал `Damage` вместо 1) | после написания сверить код с планом по пунктам |

## Заметки на будущее

- `i` это номер ящика, `arr[i]` это то, что лежит внутри.
- Максимум и минимум стартуют с первого элемента, а не с нуля.
- Для суммы старт 0, для произведения старт 1.
- Перед кодом пишу план одним-двумя строками комментарием. В плане только то, что делает сам метод, и в том порядке, в каком это идёт в коде.
- Методы называю глаголом (`FindMax`), классы существительным (`Arrays`). Имя метода должно честно говорить, что он делает.
- Имена только на английском, без транслита и без калек с русского (не `Mass`, а `Array`). Стиль PascalCase для методов и классов.
- Не называю параметры ключевыми словами (`from`), лучше `min` / `max` или `lower` / `upper`. Нейтральное имя массива: `numbers`, а не `digits`.
- Оформление по стандарту Microsoft: `i++`, `numbers[i]`, без пробелов перед скобками индексатора.
- `return` внутри цикла завершает весь метод, это удобно для поиска первого совпадения.
- Проверка аргументов стоит в начале метода, до основной работы, и выполняется один раз.
- Условие, которое внутри цикла каждый раз даёт один и тот же ответ, выносится из цикла.
- `-1` как «не найдено» подходит для индекса, но неоднозначно, если `-1` может быть настоящим результатом (например, суммой).
- Метод, который считает, ничего не печатает: вывод делает вызывающий код.
- Массив передаётся в метод по ссылке: если метод меняет элементы, меняется и исходный массив. Чтобы сохранить исходный, метод создаёт и возвращает новый.
- Чтобы получить из массива одно число (сумма, максимум, счётчик), нужна переменная-накопитель: объявляется до цикла, обновляется в цикле, возвращается после.
- Массив нельзя вывести через `Console.WriteLine(array)`: нужен цикл по элементам.
- Класс это чертёж, объект это экземпляр (`new`). Конструктор задаёт стартовые значения. `{ get; private set; }` значит «читать можно снаружи, менять только внутри класса».
- Каждый класс лежит в своём файле, имя файла совпадает с именем класса. Классы пишу как `public class`.
- Метод объекта не получает то, что уже хранится в самом объекте. Параметром передаётся только то, что приходит снаружи (урон в `TakeDamage`).
- Условие цикла должно зависеть от переменной, которая меняется внутри цикла. Один удар это одно вычитание, цикл для него не нужен.
- Переменная, которая помнит значение между повторами цикла, объявляется до цикла. Объекты, с которыми работает цикл, создаются до цикла.
- Локальные переменные пишутся с маленькой буквы (`wolf`), классы и методы с большой. Имя переменной не совпадает с именем метода (`damage`, а не `takeDamage`).
- Тест должен ломать код: брать урон больше остатка здоровья, пустой массив, сломанное оружие.
- Тесты: обычный случай, граница, пустой массив, «ничего не найдено». Ожидаемый ответ записываю до запуска, считаю внимательно по исходным числам.
